# 升级部署 - 国内代理远程数据库节点

适用节点：国内子节点，例如 `198.51.100.20`。

该类节点运行：

- `sub2api` 应用容器
- `sub2api-db-proxy`，用于数据库 TCP 转发
- `mihomo`，用于数据库访问代理
- 可选 `sub2api-app-proxy` / `mihomo-app-fallback`，用于应用兜底转发

标准升级只替换 `sub2api` 应用容器，不重建代理容器，不修改 Mihomo/GOST 配置。

## 1. 本地构建镜像

在本地源码目录执行：

```bash
VERSION=0.1.XXX
IMAGE="sub2api-custom:v${VERSION}"
ARCHIVE="sub2api-custom-v${VERSION}.tar.gz"

git status --short --branch
cat backend/cmd/server/VERSION
git rev-parse --short HEAD
```

构建镜像：

```bash
docker build \
  --pull=false \
  --build-arg VERSION="${VERSION}" \
  --build-arg COMMIT="$(git rev-parse --short HEAD)" \
  -t "${IMAGE}" \
  -f Dockerfile .
```

验证镜像版本：

```bash
docker run --rm --entrypoint /app/sub2api "${IMAGE}" --version
```

## 2. 导出镜像包

Linux / macOS：

```bash
docker save "${IMAGE}" -o "sub2api-custom-v${VERSION}.tar"
gzip -6 "sub2api-custom-v${VERSION}.tar"
sha256sum "${ARCHIVE}"
```

Windows PowerShell：

```powershell
$VERSION = "0.1.XXX"
$IMAGE = "sub2api-custom:$VERSION"
$TAR = "sub2api-custom-v$VERSION.tar"
$ARCHIVE = "$TAR.gz"

docker save $IMAGE -o $TAR
python -c "import gzip, shutil, sys; src=sys.argv[1]; dst=sys.argv[2]; f_in=open(src,'rb'); f_out=gzip.open(dst,'wb',compresslevel=6); shutil.copyfileobj(f_in,f_out); f_out.close(); f_in.close()" $TAR $ARCHIVE
Remove-Item -Force $TAR
Get-FileHash $ARCHIVE -Algorithm SHA256
```

## 5. 确认代理链路

进入部署目录：

```bash
cd /data/projects/sub2api/sub2api-deploy

VERSION="0.1.XXX"
IMAGE="sub2api-custom:v${VERSION}"
```

确认 `docker-compose.remote-db.yml` 使用本机代理入口，而不是直接连核心数据库：

```bash
cat docker-compose.remote-db.yml
```

期望包含类似内容：

```yaml
services:
  postgres:
    profiles:
      - local-data-disabled
  redis:
    profiles:
      - local-data-disabled
  sub2api:
    extra_hosts:
      - "host.docker.internal:host-gateway"
    depends_on: !reset []
    environment:
      DATABASE_HOST: host.docker.internal
      DATABASE_PORT: "15432"
      REDIS_HOST: host.docker.internal
      REDIS_PORT: "16379"
```

确认代理容器仍在：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}' | grep -E 'sub2api|mihomo|gost'
```

确认本机代理端口监听：

```bash
ss -lntp | grep -E ':15432|:16379|:7890|:7891' || true
```

确认数据库代理可用：

```bash
timeout 8 nc -vz 172.18.0.1 15432
timeout 8 nc -vz 172.18.0.1 16379
```

## 6. 切换应用容器

先确认当前应用健康：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker inspect sub2api --format '{{.Config.Image}} {{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{else}}no-health{{end}}'
curl -fsS --max-time 5 http://127.0.0.1:8080/health
```

备份 override：

```bash
if [ -f docker-compose.release.override.yml ]; then
  cp -a docker-compose.release.override.yml docker-compose.release.override.yml.bak.$(date +%Y%m%d-%H%M%S)
fi
```

写入新应用镜像：

```bash
# This override should only carry the sub2api image override. If it already
# contains other custom settings, edit only the image line manually.
cat > docker-compose.release.override.yml <<EOF
services:
  sub2api:
    image: ${IMAGE}
EOF
```

检查 compose：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  config -q
```

只重建 `sub2api`：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  up -d --no-deps --force-recreate sub2api
```

命令作用：

- `docker-compose.local.yml`：加载基础服务定义。
- `docker-compose.release.override.yml`：覆盖应用镜像。
- `docker-compose.remote-db.yml`：让应用通过 `host.docker.internal:15432/16379` 访问本机 GOST 代理。
- `--no-deps`：不启动本地 PostgreSQL/Redis，不影响 Mihomo/GOST。
- `sub2api`：只重建应用容器。

## 7. 验证

确认应用容器健康：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker inspect sub2api --format '{{.Config.Image}} {{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{else}}no-health{{end}} {{.State.StartedAt}}'
docker logs --tail=200 sub2api
curl -fsS --max-time 5 http://127.0.0.1:8080/health
```

确认应用仍走本机代理端口：

```bash
docker inspect sub2api --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -E 'DATABASE_HOST|DATABASE_PORT|REDIS_HOST|REDIS_PORT'
```

期望：

```text
DATABASE_HOST=host.docker.internal
DATABASE_PORT=15432
REDIS_HOST=host.docker.internal
REDIS_PORT=16379
```

确认数据库代理链路仍有命中：

```bash
docker logs --tail=100 sub2api-db-proxy
docker logs --tail=200 mihomo | grep -E 'db-main|DB-AUTO|DB-FALLBACK' || true
```

确认 Nginx 入口：

```bash
nginx -t
curl -fsS --max-time 5 http://127.0.0.1:8081/health || true
curl -fsS --max-time 5 http://127.0.0.1/health || true
curl -fsS --max-time 5 http://198.51.100.20:8081/health || true
```

如果节点配置了应用兜底代理，也确认这些容器没被误动：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}' | grep -E 'sub2api-app-proxy|mihomo-app-fallback|sub2api-db-proxy|mihomo'
```

## 8. 回滚

查找旧镜像：

```bash
docker images | grep sub2api-custom
```

把 override 改回旧 tag：

```bash
OLD_IMAGE="sub2api-custom:0.1.OLD"

# This override should only carry the sub2api image override. If it already
# contains other custom settings, edit only the image line manually.
cat > docker-compose.release.override.yml <<EOF
services:
  sub2api:
    image: ${OLD_IMAGE}
EOF
```

用同一组三文件 compose 命令回滚：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  up -d --no-deps --force-recreate sub2api
```

验证：

```bash
docker logs --tail=200 sub2api
curl -fsS --max-time 5 http://127.0.0.1:8080/health
docker logs --tail=100 sub2api-db-proxy
```

## 9. 禁止操作

国内代理远程数据库节点升级时不要执行：

```text
docker compose down
docker compose up -d
docker rm -f mihomo sub2api-db-proxy sub2api-app-proxy mihomo-app-fallback
docker restart mihomo sub2api-db-proxy
```

不要覆盖：

- `/data/projects/mihomo`
- `/data/projects/sub2api/sub2api-deploy/docker-compose.remote-db.yml`
- `/data/projects/sub2api-app-fallback`

这些目录和文件决定国内节点访问核心数据库和兜底转发的代理链路。
