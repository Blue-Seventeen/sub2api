# 升级部署 - 国外远程数据库节点

适用节点：国外子节点。

该类节点只运行 `sub2api` 应用容器，数据库连接到核心数据库节点 `db-main.example.com`。节点本地不运行 PostgreSQL/Redis。

标准升级只替换 `sub2api` 应用容器，不修改 Nginx，不修改防火墙，不修改核心数据库。

## 1. 本地构建镜像

在本地源码目录执行：

```bash
VERSION=0.1.XXX
IMAGE="sub2api-custom:v${VERSION}"
ARCHIVE="sub2api-custom-v${VERSION}.tar.gz"

git status --short --branch
cat backend/cmd/server/VERSION
git rev-parse --short HEAD
```

构建镜像：

```bash
docker build \
  --pull=false \
  --build-arg VERSION="${VERSION}" \
  --build-arg COMMIT="$(git rev-parse --short HEAD)" \
  -t "${IMAGE}" \
  -f Dockerfile .
```

验证镜像版本：

```bash
docker run --rm --entrypoint /app/sub2api "${IMAGE}" --version
```

## 2. 导出镜像包

Linux / macOS：

```bash
docker save "${IMAGE}" -o "sub2api-custom-v${VERSION}.tar"
gzip -6 "sub2api-custom-v${VERSION}.tar"
sha256sum "${ARCHIVE}"
```

Windows PowerShell：

```powershell
$VERSION = "0.1.XXX"
$IMAGE = "sub2api-custom:$VERSION"
$TAR = "sub2api-custom-v$VERSION.tar"
$ARCHIVE = "$TAR.gz"

docker save $IMAGE -o $TAR
python -c "import gzip, shutil, sys; src=sys.argv[1]; dst=sys.argv[2]; f_in=open(src,'rb'); f_out=gzip.open(dst,'wb',compresslevel=6); shutil.copyfileobj(f_in,f_out); f_out.close(); f_in.close()" $TAR $ARCHIVE
Remove-Item -Force $TAR
Get-FileHash $ARCHIVE -Algorithm SHA256
```

## 3. 上传到国外节点

把 IP 替换成实际国外子节点 IP：

```bash
NODE_IP="203.0.113.30"
scp "${ARCHIVE}" root@${NODE_IP}:/data/projects/sub2api/
```

在节点上校验：

```bash
cd /data/projects/sub2api

VERSION="0.1.XXX"
IMAGE="sub2api-custom:v${VERSION}"
ARCHIVE="sub2api-custom-v${VERSION}.tar.gz"

sha256sum "${ARCHIVE}"
```

## 4. 节点导入镜像

```bash
cd /data/projects/sub2api

VERSION="0.1.XXX"
IMAGE="sub2api-custom:v${VERSION}"
ARCHIVE="sub2api-custom-v${VERSION}.tar.gz"

gunzip -k "${ARCHIVE}"
docker load -i "sub2api-custom-v${VERSION}.tar"
docker image inspect "${IMAGE}" --format '{{.Id}} {{.Size}} {{.Created}}'
```

## 5. 确认远程数据库配置

进入部署目录：

```bash
cd /data/projects/sub2api/sub2api-deploy

VERSION="0.1.XXX"
IMAGE="sub2api-custom:v${VERSION}"
```

确认 `docker-compose.remote-db.yml` 指向核心数据库域名和标准端口：

```bash
cat docker-compose.remote-db.yml
```

期望包含类似内容：

```yaml
services:
  postgres:
    profiles:
      - local-data-disabled
  redis:
    profiles:
      - local-data-disabled
  sub2api:
    depends_on: !reset []
    environment:
      DATABASE_HOST: db-main.example.com
      DATABASE_PORT: "5432"
      REDIS_HOST: db-main.example.com
      REDIS_PORT: "6379"
```

如果当前节点实际使用别的端口或域名，以线上现有 `docker-compose.remote-db.yml` 为准，不要用本地文件覆盖。

## 6. 切换应用容器

先确认当前状态：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker inspect sub2api --format '{{.Config.Image}} {{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{else}}no-health{{end}}'
curl -fsS --max-time 5 http://127.0.0.1:8080/health
```

备份 override：

```bash
if [ -f docker-compose.release.override.yml ]; then
  cp -a docker-compose.release.override.yml docker-compose.release.override.yml.bak.$(date +%Y%m%d-%H%M%S)
fi
```

写入新应用镜像：

```bash
# This override should only carry the sub2api image override. If it already
# contains other custom settings, edit only the image line manually.
cat > docker-compose.release.override.yml <<EOF
services:
  sub2api:
    image: ${IMAGE}
EOF
```

检查 compose：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  config -q
```

只重建 `sub2api`：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  up -d --no-deps --force-recreate sub2api
```

命令作用：

- `docker-compose.local.yml`：加载基础服务定义。
- `docker-compose.release.override.yml`：覆盖应用镜像。
- `docker-compose.remote-db.yml`：禁用本地 PostgreSQL/Redis，并把应用连接到核心数据库。
- `--no-deps`：不启动本地数据库依赖。
- `sub2api`：只重建应用容器。

## 7. 验证

确认容器健康：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker inspect sub2api --format '{{.Config.Image}} {{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{else}}no-health{{end}} {{.State.StartedAt}}'
docker logs --tail=200 sub2api
curl -fsS --max-time 5 http://127.0.0.1:8080/health
```

确认应用仍连接核心数据库：

```bash
docker inspect sub2api --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -E 'DATABASE_HOST|DATABASE_PORT|REDIS_HOST|REDIS_PORT'
```

期望：

```text
DATABASE_HOST=db-main.example.com
DATABASE_PORT=5432
REDIS_HOST=db-main.example.com
REDIS_PORT=6379
```

确认 Nginx 入口：

```bash
nginx -t
curl -fsS --max-time 5 http://127.0.0.1/health || true
curl -kfsS --max-time 5 https://api.example.com/health || true
curl -kfsS --max-time 5 https://api2.example.com/health || true
```

## 8. 回滚

查找旧镜像：

```bash
docker images | grep sub2api-custom
```

把 override 改回旧 tag：

```bash
OLD_IMAGE="sub2api-custom:0.1.OLD"

# This override should only carry the sub2api image override. If it already
# contains other custom settings, edit only the image line manually.
cat > docker-compose.release.override.yml <<EOF
services:
  sub2api:
    image: ${OLD_IMAGE}
EOF
```

用同一组三文件 compose 命令回滚：

```bash
docker compose \
  -f docker-compose.local.yml \
  -f docker-compose.release.override.yml \
  -f docker-compose.remote-db.yml \
  up -d --no-deps --force-recreate sub2api
```

验证：

```bash
docker logs --tail=200 sub2api
curl -fsS --max-time 5 http://127.0.0.1:8080/health
```

## 9. 禁止操作

国外远程数据库节点升级时不要执行：

```text
docker compose down
docker compose up -d
docker rm -f postgres redis
```

不要删除或覆盖远程节点上的 `.env` 和 `docker-compose.remote-db.yml`。这两个文件决定节点身份和数据库连接方式。
