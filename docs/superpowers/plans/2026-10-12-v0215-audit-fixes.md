## Task 1: 原子化推广关系修改

所有权：`backend/internal/repository/promotion_repo_core.go`、`promotion_repo_query.go`、`backend/internal/service/promotion_service.go`，以及相关推广测试；可新增仓库级推广事务 helper 文件。

- 保留 PromotionRepository 的既有签名，无 DDL。SetPromotionParent 和 RemovePromotionDirectDownline 使用显式 READ COMMITTED 事务及固定 advisoryLockHash("sub2api:promotion:parent-graph") 的 pg_advisory_xact_lock。
- 获锁后通过同一个 sql.Tx 重新读取关系、已落地消费和祖先链，不能使用 r.db 绕过事务。self 来源同父幂等、不同父返回 AlreadyBound、首次绑定消费后拒绝；admin 来源保留消费后重绑和备注修改；解绑允许修复历史循环。
- 服务保留格式校验、邀请码解析及 EnsurePromotionUser；仓库内校验为权威，避免无保护的递归预查阻塞历史坏数据。
- 祖先链发现自身或重复节点返回 ErrPromotionBindCycle。所有递归查询有限终止：仅 ID 的 CTE 用 UNION；含深度的 CTE 用 visited path（包含根），保留 32 层上限；批量按 root/user 去重，排除根自身。有限关系链也不能重复显示自身。
- 回归：真实 PostgreSQL 两独立连接互绑、多节点并发成环、抢绑、同父幂等、管理员操作、锁等待/取消、历史循环有限查询及解除。
- 先保存 RED 证据；实现后运行推广服务和真实仓库定向测试。主线程提供隔离测试环境，不得将 integration harness 指向业务库。

## Task 2: 免费统一倍率跳过费用预留

所有权：`backend/internal/service/unified_rate.go`、`billing_inflight_reservation.go`、`backend/internal/handler/gateway_inflight_reservation.go`、`backend/internal/server/middleware/api_key_auth.go`，以及这些行为的相关测试。

- 导出 HasZeroChargeUnifiedRate(user *User) bool：非 nil 且 EffectiveUnifiedRateMultiplier()==0。与已有鉴权、实扣规则复用，禁用零倍率、负倍率和 nil 用户不判免费。
- 共用估算入口提前返回 (0,true)，在模型解析和定价前处理明确免费。
- handler 预留入口在 estimator 和 fail_closed_on_unpriced 检查前返回 no-op；底层 reserveInflight 即使收到正 estimate 也不读取余额、不操作 Redis、不续期。
- 不改 Redis Lua、配置、一般正倍率估算或已有预留成员。
- 回归：重叠免费请求、零/负余额、未知模型及严格定价、直接正估算预留、文本/图片/视频/音频等共用路径。对照付费请求保留预留/拒绝、Key 限制和订阅规则。
- 先记录 RED，再做最小实现并运行 service、handler、middleware 定向测试。

## Task 3: 浏览器稳定会话与异步提交守卫

所有权：`frontend/src/api/authSession.ts`（新增）、`auth.ts`、`client.ts`、`tokenRefresh.ts`、`frontend/src/stores/auth.ts` 及相关前端测试。若 OAuth 调用方必须修改，先向主线程说明必要性；优先在公共 persistOAuthTokenContext/setToken 边界完成兼容。

- 持久化非权限用途的 auth_session_id，成功建立新会话时生成，退出/失效时清除；正常 Token 轮换与资料变化保持稳定。现有持久登录可无损补齐。
- API 与 Store 使用同一会话提交工具，密码/2FA/注册/Passkey/OAuth 均覆盖，避免 storage 先写而 Store 后写的窗口；调用顺序和 HTTP AuthResponse 兼容。
- refreshUser 成功及失败、续期结果、OAuth/注册后续 await、退出和认证错误均在提交前检查身份；旧操作统一拒绝 AUTH_SESSION_CHANGED，不覆盖 user/runMode/storage、不退出新会话、不重新启动计时器。
- Axios 请求携带内部会话标识（不发送新 HTTP header）；401 刷新、重试和清理前检查，旧用户请求不能用新用户凭证重发。刷新 single-flight 以会话隔离，保留同会话跨标签页协调。
- 退出立即清本地旧会话；服务端吊销使用旧 refresh token，迟到结果不能清新登录。保留 TOKEN_REFRESH_BUFFER=120秒和后端 JWT 期限。
- 回归：延迟旧 admin profile 成功/401、新 user 登录、退出后迟到成功、同账号重新登录、晚到退出、新旧续期并发、同会话正常刷新/peer rotation、多登录入口。使用 deferred promises 和真实 Store/API 层行为，mock 仅网络边界。
- 保存 RED 证据，再实现并运行相关 Vitest、typecheck、lint:check。
