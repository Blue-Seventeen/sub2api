# Sub2API v0.2.11 Selective Sync and Streaming Delivery Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Selectively absorb compatible upstream v0.2.11 changes into the custom fork and prove that every supported streaming relay emits upstream data before the upstream response completes.

**Architecture:** The custom fork remains the product baseline. Upstream changes are imported file-by-file only when they are additive or can be adapted without bypassing custom routing, billing, subscription, usage, promotion, proxy, and compatibility behavior. Streaming paths remain separate from buffered JSON paths and are verified with delayed synthetic upstreams plus real HTTP clients.

**Tech Stack:** Go, Gin, `net/http`, `httptest`, PostgreSQL/Redis-compatible services, Vue 3/TypeScript where API contracts change, Docker Compose.

## Global Constraints

- Preserve custom billing, balance deduction, subscription anchor rolling windows, multi-subscription deduction, Promotion/Affiliate behavior, CompatibleGateway/NewAPI-style routing, GLM/Qwen/Kimi/DeepSeek/MiniMax channels, proxy/scheduler behavior, usage redaction, `models_list_config` admission semantics, and Live-disabled behavior.
- Do not run `git reset --hard`, `git checkout`, or `git clean`.
- Do not merge the upstream tree wholesale and do not delete custom files solely because `v0.2.11` deleted them.
- Do not modify historical migrations; add a new migration only if an absorbed upstream schema change requires it.
- Production code changes follow test-first debugging: add a minimal failing regression test, run it to prove the expected failure, implement one root-cause fix, then rerun focused and broad tests.
- Runtime version remains the upstream numeric version; `-custom` is allowed only in release tags, image tags, and archive names.
- Do not claim streaming is fixed until a client receives the first event before a delayed upstream sends its second event.
